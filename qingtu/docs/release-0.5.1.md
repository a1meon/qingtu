# 轻图 0.5.1

恢复已配置的 0.4.x 应用内更新，轻量安装包大小仍为 Windows x64 9.28 MB、Mac arm64 11.04 MB、Mac x64 11.49 MB。

Windows 正式 NSIS 0.4.3–0.4.8 通过 latest.yml 直接更新。沿用旧应用 GUID、自定义目录、32/64位注册视图和每用户/全用户作用域；全用户安装经 UAC 的原用户进程启动。新文件及卸载器先完整暂存，同卷备份与替换，任何替换失败均恢复旧文件；登记失败恢复全部修改值及不存在状态。提交标记持久化后才清理明确的旧 Electron 文件，未知文件、项目和原图保持不动。多份不同目录的安装无明确 /D 时安全中止，避免更新错误副本。

Mac 具备 Sparkle 和原公钥的正式 0.4.4–0.4.8 先自动更新完整过渡版 0.4.9（arm64 126,366,175 字节，x64 134,119,605 字节）。过渡版启动后检查独立轻量通道，再经原 Sparkle 原位安装 0.5.1。需要两轮确认下载和重启，无需手动下载、解压或拖 DMG。过渡版兼容 macOS13.0；轻量版要求13.3。系统门槛经过签名，在检查、下载、安装三处检验，传入本机 Sparkle appcast；13.0–13.2 保留完整可用版本。

旧客户端忽略 minimumSystemVersion，Sparkle 的应用安装验证也不替旧 feed 自动补上门槛，因此不能把旧 mac-* 通道直接指到轻量 ZIP。每个后续 latest 发行版都必须保留旧通道、过渡分片及 mac-light-*，否则尚未迁移的旧用户会再次检查失败。

0.4.0/0.4.1 没有更新客户端，0.4.2 没有正式配置/签名基线，仍需安装新包一次。Mac0.4.3 曾用于隔离测试，不能据此声称所有正式0.4.3均可迁移。0.5.0 Mac 沿用应用内下载 DMG 的模式；本次恢复的是原0.4.x的 Sparkle 安装链。

验证：302项 Node 测试、265项轻量后端测试、Go真实文件系统中断/回滚测试、13项必需界面/质量检查及build通过。隐藏屏幕外的实际Mac fixture完成0.4.8→0.4.9→0.5.1两次Sparkle替换、重启，最终Neutralino实际导入、项目重载、PNG和JPEG编码及同名编号导出成功。旧项目完整清单与原图字节一致。正式0.4.4与0.4.8的Mac更新/下载/源解析代码逐字节一致。四份正式Mac归档的清单、分片/整包哈希、官方Sparkle签名验证均通过，验证器仅读取公钥。Windows真实NsisUpdater完成下载和SHA-512检查；Windows原生安装与Intel Mac运行未在此Mac上执行。

附件共18个，312,728,516字节。发行前空间不足，用户再次确认后删除最早v0.4.7的15个附件（407,197,206字节）；此前已匿名完整下载并逐字节校验到release/archive-v047。保留v0.4.8、v0.5.0，上传后预计占用772,082,321字节，低于1,000,000,000字节限额。
