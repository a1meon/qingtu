# 轻图 Implementation Plan

> **For agentic workers:** 使用当前会话逐项实施、按任务验证。素材由三个只负责图片的 agent 生成。

**Goal:** 基于第 2 套深色界面交付真实图片压缩及尺寸调整的跨平台桌面应用。

**Architecture:** React 呈现队列和设置，Electron 主进程接收受限文件操作。独立 sharp 引擎负责编码、尺寸计算和目标搜索，桌面与本地开发预览共用服务。

**Tech Stack:** React 19、Vite 6、Electron 44、sharp 0.35、Phosphor Icons、electron-builder 26、Node test runner。

**Spec:** `docs/spec.md`

## Global Constraints

- macOS 与 Windows；无服务器、无账号，图片仅本地处理。
- 无损模式保留像素、格式和尺寸；目标模式输出不超过用户指定体积。
- 沿用第 2 张设计的深色、暖琥珀色、大图、底部队列、右侧设置布局。
- 导出不覆盖原始或已有文件，取消后停止后续任务。

### Task 1: 压缩引擎

**Files:** `engine/image.mjs`、`engine/service.mjs`、`tests/image.test.mjs`、`tests/service.test.mjs`

**Interfaces:** `processImage(buffer, settings) -> {buffer,width,height,format,quality,unchanged}`；`dimensions(metadata, settings) -> {width,height}`。服务以 UUID 识别导入文件和结果，不接受 renderer 任意路径。

- [x] 编写目标上限、PNG/WebP 解码像素、JPEG 像素和 EXIF、尺寸、透明度、错误及重名导出测试。
- [x] `node --test tests/image.test.mjs tests/service.test.mjs` 确认因模块缺失失败。
- [x] 实现尺寸验证与比例计算；质量从 1–100 搜索，JPEG 使用 mozjpeg，WebP 使用 quality，PNG 使用 palette quality。无损结果解码比对且不增大体积。
- [x] 跑同一测试命令确认通过。

### Task 2: 桌面工作台

**Files:** `src/App.jsx`、`src/styles.css`、`src/api.js`、`desktop/main.cjs`、`desktop/preload.cjs`、`scripts/dev-bridge.mjs`

**Interfaces:** `importFiles([{name,base64}])`、`samples()`、`process(id,settings)`、`chooseFolder()`、`save(token)`、`remove(id)`、`windowAction(action)`。

- [x] 大图按 contain 显示，前后 slider 共用像素位置；左右键可操作；底部横向队列可滚动。
- [x] 右侧尺寸设置用原图比例联动宽高；切模式禁用无损时的格式和尺寸。对所有异步操作显示 loading/error。
- [x] 主进程开启 sandbox/contextIsolation，IPC 仅允许本地窗口。独占创建导出文件并追加数字后缀。
- [x] 启动本地预览并测试导入、目标大小、保持比例、无损、移除、导出和取消。

## 验证记录

最终按最新用户反馈重写为亮色、默认无损编码、底部同尺寸导入格和整数 MB。30 项测试通过；三张真实图片均导出 768 × 512、1,048,576 字节 PNG；Electron 原生导出通过。Windows NSIS 编译器不能在当前 ARM Mac 运行，交付完整 Windows ZIP 并提供 Windows runner 安装包构建流程。最终设计 QA 以最新用户布局约束覆盖早期图片。
